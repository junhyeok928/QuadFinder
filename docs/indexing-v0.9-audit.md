# 인덱싱 구조 개선 검증 (0.9.0)

- 인덱스 본체를 메모리 Map + 전체 JSON 저장에서 SQLite WAL 저장소로 변경했다. 512개 단위 페이지 조회와 변경분 트랜잭션을 사용하며, 기본 디스크 인덱스의 250,000개 제한을 제거했다.
- 이전 JSON 캐시는 최초 1회 가져온다. 원본 캐시는 보존하며 이후에는 SQLite에만 변경분을 기록한다.
- Windows FindFirstFileEx/FindNextFile 결과에서 이름·크기·시각·속성을 함께 가져온다. 파일별 lstat 실패가 같은 폴더의 다른 파일 수집을 막는 문제를 줄였다. 네이티브 도우미는 장시간 유지하며 페이지 단위 JSON으로 통신한다.
- 260자를 넘는 경로를 지원한다. .NET Framework의 Path.GetFullPath/Combine 길이 제한도 피하도록 로컬 절대 경로를 별도 검증한다.
- 접근 오류를 EACCES/EPERM, ETIMEDOUT, ENOENT/ENOTDIR, 기타로 구분한다. 확인되지 않은 삭제로 캐시를 지우지 않으며, 복구되거나 실제 삭제된 경로의 오류는 해제한다.
- 상태 표시줄의 인덱싱 문구를 클릭하면 오류 경로와 관리자 도우미 실행 버튼을 볼 수 있다. 승격은 사용자 UAC 승인 후 읽기 전용 도우미에만 적용한다. 파일 관리자 자체 승격이나 ACL/소유권 변경은 하지 않는다.
- 일반 권한으로 속성을 재확인하지 못해도 인덱싱 도우미가 수집한 숨김·시스템 속성을 덮어쓰지 않는다.
- `.git`과 `node_modules`를 포함한다. 네트워크 경로·네트워크 드라이브, 재분석 지점, 앱 내부 데이터, 휴지통, System Volume Information은 제외한다.

## 검증

- 단위 및 실제 파일 테스트 54개: SQLite 250,010건 저장·재개, 변경 없는 재확인 시 DB 데이터 유지, 부모별 삭제 검증, 오류 복구·분류, 530개 이상의 폴더 항목 페이지 전송, 유니코드·긴 경로, 읽기 외 요청과 네트워크 요청 거부를 포함한다.
- 관리자 도우미와 동일한 이름 있는 파이프 통신 및 연결 종료를 실제 프로세스로 검증했다. 자동 검사에서는 UAC 승격 요청을 하지 않는다.
- 실제 Electron 검사: 검색과 파일 작업, 실행 취소, 테마·확대, 사이드바·패널 조절, 마우스 뒤로가기, 인덱싱 진단 UI 및 오류 경로 HTML 이스케이프를 확인한다.
- 실제 로컬 사용자 폴더와 기존 D:\deploy 범위의 읽기 전용 수집: 49,490개 파일·폴더 / 7,969개 디렉터리 / 14.177초 / 권한 부족·시간 초과·기타 오류 0개. 환경에 따른 참고 수치이며 이전 메모리 인덱서와 동일 조건의 성능 비교는 아니다.

## 남은 한계

- MFT/USN 직접 인덱싱은 구현하지 않았다. 최초 수집 및 종료 중 변경 확인을 위한 시작 시 전체 순회는 여전히 필요하다. 실행 중에는 기존 변경 알림으로 증분 갱신한다.
- 실제 UAC 승인과 그에 따른 보호 폴더 접근 범위 확대는 사용자 환경에서 확인해야 한다. 관리자 권한도 SYSTEM/TrustedInstaller 등 모든 보호 영역의 접근을 보장하지 않는다.
- 검색 결과는 상위 1,000개를 표시하며 파일 본문을 검색하지 않는다. SQL은 이름 후보를 먼저 좁히지만 전체 파일명 검색용 역색인이나 USN 저널 재생 기능은 아직 없다.
