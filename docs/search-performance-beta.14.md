# 검색 성능 개선 — 0.14.0-beta.14

- 파일명의 3글자 이상 연속 문자열은 SQLite FTS5 trigram 색인으로 후보를 찾습니다. 1~2글자와 확장자·경로·크기 조건만 있는 검색은 기존 순회 방식을 유지합니다.
- 최대 표시 개수보다 한 개 더 찾으면 반환합니다. 처음에는 1,000개를 표시하고, 결과가 더 있으면 `1,001개 이상`으로 표시합니다. 더 불러오기를 통해 끝까지 확인하면 정확한 개수로 전환됩니다. 전체 개수를 백그라운드에서 별도로 세지는 않습니다.
- 검색 결과를 표시하기 전에 Windows 도우미를 실행해 모든 파일의 속성을 다시 읽던 단계를 제거했습니다. 숨김·시스템·읽기 전용은 인덱싱 때 수집하며 변경 감시에 따라 갱신됩니다.
- 검색어 분해와 와일드카드 정규식 생성은 요청당 한 번만 수행합니다.
- 기존 데이터베이스는 최초 실행 때 검색 색인을 한 번 생성합니다. 이 과정에는 추가 시간과 디스크 공간이 필요하며, 원본 파일을 다시 읽지는 않습니다.

## 검증

- 전체 테스트 100개 통과. 최종 검색 페이지 처리 변경 후 관련 테스트 5개 재검증 통과.
- 한글·정규화·따옴표·와일드카드·필터·이름 변경·삭제·이전 SQLite 전환·페이지 확장 검사.
- 로컬 실행용 패키지 검증 통과.
- `node scripts/search-bench.cjs`: 가상 파일명 20,000개, 메모리 DB, 5회 중앙값. 실행 환경에 따라 달라집니다.
  - 단일 결과 검색: 1.30ms → 0.25ms
  - 결과 없음: 1.14ms → 0.04ms
  - 다수 결과: 27.09ms → 1.78ms (이전 전체 20,000개 계산, 변경 후 1,001개 확인)
- 위 수치는 조회 단계만 포함하며 앱 시작·실제 디스크·화면 표시 속도를 뜻하지 않습니다.

로컬 결과물: `release/0.14.0-beta.14/QuadFinder-win32-x64`.
