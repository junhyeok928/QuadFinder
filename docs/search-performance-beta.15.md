# 검색 반응 개선 — 0.14.0-beta.15

## 확인된 원인

2026-11-09 실행 중이던 설치본은 beta.13이었습니다. beta.14는 별도의 로컬 실행 폴더에만 있어서 설치본에는 이전 개선이 적용되지 않았습니다.

실제 색인은 약 125만 항목, 파일 크기 약 2.23GB였습니다. 기존 파일명 부분 검색 쿼리를 읽기 전용으로 측정했을 때 `보고` 22,765ms, `없는검색어xyz` 23,567ms, `프로젝트` 22,875ms가 걸렸습니다. 이 수치는 DB 조회 단계이며 화면 표시 시간은 포함하지 않습니다.

## 변경

- 1~2글자 파일명 검색은 정규화된 파일명만 메모리에 준비하고 일치한 파일의 상세정보만 읽습니다.
- 3글자 이상 문자열은 기존 FTS 색인을 사용합니다. 확장자와 문서·이미지 필터도 가능한 한 이름 단계에서 먼저 거릅니다.
- 이름 추가·변경·삭제는 메모리 목록에 바로 반영합니다. 준비 중 발생하는 변경도 보존합니다.
- 메모리 준비와 시작 시 검색 범위 정리를 작은 묶음으로 처리합니다. 범위 정리는 파일 상세 JSON을 전부 읽지 않습니다.
- 검색과 큰 폴더 갱신 도중 실행권을 양보하여 새 검색 요청을 처리합니다. 결과가 없는 검색도 취소할 수 있습니다.
- 입력 대기를 180ms에서 35ms로 줄였습니다. 한글 조합 중 중복 요청을 막고 조합 완료 시 검색합니다.
- 연속 검색에서는 기존 결과를 유지하다 새 결과 목록만 바꿉니다. 오래된 응답은 입력 즉시 무효화합니다.
- 검색 오류를 해당 요청에 바로 전달하여 20초 제한까지 기다리지 않도록 수정했습니다.

## 실제 색인 읽기 전용 측정

`node scripts/search-live-bench.cjs <index.sqlite 경로>`로 재현할 수 있습니다. 결과 파일명이나 경로는 출력하지 않습니다.

| 없는검색어xyz | 3.19ms | 0.17ms | 0.11ms |
| 프로젝트 | 3.16ms | 0.47ms | 0.47ms |
| a | 44.69ms | 25.51ms | 16.62ms |
| 없는 | 80.01ms | 70.06ms | 72.21ms |

이름 1,251,314개 준비에 5,775ms가 걸렸고 준비 직후 측정 프로세스의 JavaScript 힙은 약 168MB였습니다. 첫 실행 준비·운영체제 파일 캐시·동시 인덱싱·화면 렌더링에 따라 체감 시간은 달라집니다. 모든 검색이 이 시간 이내라는 보장은 아닙니다. 특히 파일명 조건 없이 경로·크기만 검색하면 상세정보를 많이 확인할 수 있습니다.
